| 路径 | 性质 | 编辑入口 |
|---|---|---|
| `classic-folk-cases/*.md` | 28 个参考方向，待开发 | 每个 Markdown 是该主题唯一编辑源 |

## 每篇主题包含什么

民俗主题设定 → 案发现场疑点 → 关键破案线索 → 侦探拼图过程 → 最终反转，以及建议玩法衔接、开发校验与来源。它们是**结构化摘要与风险备注，不是原聊天逐字备份**，更不是已经接入游戏的成品。

原参考中的超自然说法、精确延时药效、记忆转移等仅保留为虚构方向；每篇指出需重写或验证之处。流产、出身、疾病和血缘不是罪责；反派的私刑判断不代表作品立场。

## 怎样扩容

复制一个主题的 frontmatter 与章节格式，使用**无数字前缀的稳定英文短横线文件名**。`id` 全库唯一，例如 `theme-new-motif`。在相应目录新增 `.md`，然后：

```sh
python3 -m src.folk_parser build
python3 -m unittest discover -s tests
```

测试中的 58 是本次验收基线；新增主题后相应更新数量断言。解析器本身没有条数限制。

## 怎样变成可玩案

不要把 `planned` 直接改成 `playable`。先创作原创人物、时间线、线索出处、失败反馈和反转伏笔，再参考 `playable/lamplife/case.json` 建立同格式数据与 `case.md`。至少手动通关，并通过条件图校验后才计入可玩数；仅写一篇梗概不算完成。

连续四案的生成方式：

```sh
python3 cases/authoring/serial/build_serial.py
python3 -m src.folk_parser build
```

不要同时手改它们的输出 JSON 与创作源，否则下次生成会覆盖 JSON。旧 `chapters/*.js` 已撤去；游戏仍可双击 HTML，是因为提交了生成的 `data.js`，不是因为另存了一份手写剧本。

## 权利与剧透

参考材料来自用户提供的清单，参考标题可能与已有作品相同，尚未独立核实归属。**主题目录不等于获得改编授权。** 正式发行应做权利核验，不照搬既有作品的角色、对白、情节或美术。反转放在折叠区，但明文源码必然含剧透。
